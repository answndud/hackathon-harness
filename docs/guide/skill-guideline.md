# 시험용 스킬 적용 지침

이 문서는 과제 수행 에이전트용이다. 응시자용 사용법은 [실전 가이드](./skill-user-guide.md)를 참고한다.

## 우선순위와 제한

시험의 최신 공지와 과제 README, 작업 환경의 상위 지침이 우선한다. 하네스 AGENTS.md와 이 지침을 스킬 호출 전에 직접 읽고, 충돌하는 원본 스킬 절차는 적용하지 않는다. 하네스의 실제 clone 경로를 기준으로 파일을 찾으며 과제의 기존 AGENTS.md를 덮어쓰지 않는다.

- 과제·결과물 외부 전송, git push, PR, 배포, Computer Use 자동 조작은 하지 않는다. 화면은 응시자가 직접 검증한다.
- 현업 담당자에게 전달할 질문은 응시자가 직접 보내도록 초안을 제공한다. 화면 조작이나 메시지 자동 전송을 시도하지 않는다.
- 자동 커밋은 수행하지 않는다. 존재하지 않는 도구·모델을 호출하지 않는다. 허용 모델과 도구만 사용한다.
- 후속 서술형에서 AI 이용이 금지된다는 안내를 따른다. 본 과제 중에는 사용자가 결과물의 선택과 근거를 이해하도록 짧게 설명한다.

## 설치와 호출

시험 시작 후 이 저장소를 clone하고 과제 디렉터리를 확인한다. 저장소 루트에서 `bash scripts/install-skills.sh <과제_디렉터리>`를 실행한다. 기존 동일 이름은 SKIP이며 새 버전이 설치된 것은 아니다. 스킬은 과제 작업 공간의 `skills/<이름>/`에 복사되며 자동 검색이 보장되지 않는다. 과제 내 복사 파일의 내용과 경로를 확인한다.

설치 후 SKIP된 동일 이름 스킬은 기존 파일이므로 실제 내용을 확인하고 시험 지침을 우선 적용한다. 필요한 스킬은 과제 작업 공간의 `skills/<이름>/SKILL.md`와 관련 참조 파일을 직접 읽어 적용한다. SKIP된 파일이 하네스와 다르면 clone한 하네스의 해당 파일을 직접 읽는다. 등록을 위해 임의로 세션을 종료하거나 재시작하지 않는다. 스킬·참조 파일이나 기능이 없다면 사실을 알리고 아래 원칙을 직접 적용한다. 9개를 일괄 실행하지 않는다.

## 공통 진행

1. README·제출 지침·기존 코드와 데이터·실행 방법을 확인하고 변경 전 기준 상태를 파악한다.
2. 목표, 필수 기능, 제약, 근거, 미확인 사항과 검증 방법을 짧게 분리한다. 중요한 질문을 우선순위로 최대 5개씩 제시한다.
3. 업무 사실은 자료나 현업 담당자의 답을 우선한다. 담당자 답변이 명세와 충돌하면 사용자에게 차이를 알린다. 추측은 가정으로 표시한다.
4. 여러 단계의 작업이면 필수 범위·작업 순서·의존 관계와 검증을 짧게 계획한다. 필수 기능의 작은 입력→처리→출력 경로부터 구현하고 핵심 업무 규칙은 독립 기대값으로 검증한다.
5. 오류는 재현·로그 확인·가설 검증·최소 수정·재검증 순서로 처리한다. 시험 시간과 필수 범위를 고려한다.
6. 요구사항별 구현과 실행 증거를 대조한다. 미커밋·미추적 파일도 검토하고 완료·실패·미검증을 구분한다.
7. 중요한 결정·이유·변경 파일·검증 결과·한계를 간결하게 보고한다. 사용자가 결정해야 할 업무상 선택만 확인하고, 합의된 범위의 세부 작업은 계속한다.

## 스킬별 시험용 조정

| 스킬 | 적용 지점과 조정 |
|---|---|
| grilling | 자료와 코드를 먼저 확인하고 결과를 바꾸는 질문을 최대 5개씩 준비한다. 응시자가 직접 질문하며, 핵심 업무 규칙·근거·미확인 사항과 검증 기준을 과제 문서에 기록하고 답변을 반영한다. |
| plan | 확인된 요구사항을 바탕으로 최소 기능, 작업 순서·의존 관계와 검증을 짧게 계획한다. 서브에이전트는 허용되고 독립 작업이 있을 때만 고려한다. |
| implement | 합의된 필수 기능을 작은 수직 단위로 구현하고 검증한다. 자동 커밋하지 않는다. |
| test-and-debug | 중요한 규칙은 독립 기대값과 경계 사례로 검증한다. 오류는 재현·근거·가설·최소 수정·재검증으로 처리한다. |
| create-verification-skill | 반복 검증이 필요한 경우에만 사용한다. 시험에서 금지된 화면 자동 조작을 생성·실행하지 않는다. CLI·API 검증과 사람이 직접 할 화면 체크를 구분한다. |
| code-review | 요구사항과 품질을 별도로 검토한다. 커밋 diff뿐 아니라 작업 트리와 신규 파일도 확인한다. 서브에이전트가 없으면 순차 검토한다. |
| verification-before-completion | 최종 관련 변경 이후 실제 실행 결과를 확인한다. 변경이 없으면 적절한 기존 증거를 재사용할 수 있다. |
| benchmark-checklist | 성능 비교가 필요할 때 같은 조건·실제 출력·오류·반복 실행을 확인한다. 데이터 분석의 인과 검증을 대체하지 않는다. |
| handoff | 세션 전환이 필요할 때만 보존되는 작업 경로에 현재 목표, 결정, 파일, 검증, 실패와 다음 행동을 기록한다. |

## 데이터 판단

집계 단위·시간·분자와 분모·단위·결측·중복·재검사 처리 기준을 확인한다. 예측에서는 예측 시점 이후 정보 누수를, 배정에서는 제약 충족과 해가 없는 경우를 검토한다. 관측과 추정, 가정과 결과를 혼동하지 않는다.

## 제출 전

필수 파일 경로와 형식, 저장 상태, 실행 방법과 마지막 검증을 확인한다. 관련 코드가 변경됐으면 영향받는 검사를 다시 실행한다. 확인하지 못한 결과는 미검증으로 기록한다. 시간과 제출 화면 안내를 확인하며 응시자가 직접 최종 제출한다.
