# 작업 보고 기록 지침

여러 Codex 세션이 과제 작업 공간을 공유할 때 작업별 진행 상황과 검증 근거를 전달한다. 시험 규칙·과제 지침과 기존 기록 체계를 우선한다. 이 폴더의 지침은 하네스에 보관하고, 실제 보고서는 쓰기가 허용된 과제 작업 공간에만 만든다. 단일 세션이거나 작업이 작으면 기존 과제 문서를 재사용한다.

## 파일명과 소유권

- 총괄이 작업별로 고유하고 내용을 알아볼 수 있는 이름을 배정한다. 파일명은 `<순번>-<작업명>.md` 형식으로 정한다. 순번은 `01`부터 시작하는 두 자리 이상의 숫자이며, 작업명은 영문 소문자·숫자·하이픈만 사용한다. 예: `01-core-calculation.md`, `02-result-api.md`, `03-results-screen.md`.
- 순번은 **보고서 파일이 최초 생성되는 순서**에 따라 부여한다. 새 보고서를 생성할 때 같은 폴더에 존재하는 보고서들의 순번 중 최댓값에 1을 더한다. 기존 보고서의 삭제·이름 변경·작업 완료 여부와 관계없이 사용된 순번을 재사용하거나 기존 순번을 재정렬하지 않는다. `README.md`는 순번 부여 대상에서 제외한다.
- **순번 배정과 파일 생성은 총괄이 관리한다.** 여러 세션이 동시에 작업하더라도 순번 중복이나 충돌이 발생하지 않도록 총괄이 생성 순서를 확정하고 파일명을 담당 세션에 전달한다. 담당 세션은 임의로 순번을 배정하거나 파일명을 변경하지 않는다.
- 생성 전에 동일한 경로와 순번이 존재하는지 확인하고 기존 파일을 덮어쓰지 않는다. 동일한 작업의 보고서가 이미 있으면 새 파일을 만들지 않고 기존 파일의 작성 책임을 넘겨받아 갱신한다. 서로 다른 작업에 유사한 이름이 필요한 경우 총괄이 구체적인 작업명으로 구분한다.
- 작업을 다른 세션에서 이어받더라도 최초 배정된 파일명과 순번을 유지한다. 하나의 보고서는 지정된 담당 세션 한 곳만 수정한다. 인수인계 시 기존 담당자의 작업 종료를 확인하고 수정 책임을 새 세션으로 넘긴 뒤 같은 보고서를 갱신한다. 총괄·추적 세션은 보고서를 읽고 검토하되 내용을 수정하지 않는다.
- 같은 폴더에 접근할 수 없는 별도 작업 공간이나 worktree에서는 보고서가 자동 공유되지 않는다. 허용된 방식으로 응시자가 전달하거나 총괄이 실제 경로를 읽는다. 쓰기 불가 시 채팅으로 보고하고 한계를 알린다.

## 작업 보고와 기술 부채의 구분

- `work/`는 담당 작업의 진행, 구현 위치, 결정과 실제 검증을 기록한다. 후속 조치가 필요한 문제를 발견하면 식별할 수 있을 만큼 한 줄로 적는다. 아직 부채 파일이 없다면 '부채 등록 요청'이라고 표시한다.
- `debt/`는 중요한 미해결 문제의 영향·위험도·대응·검증 이력을 관리한다. 부채 상세 내용과 최신 해결 상태는 해당 부채 파일을 기준으로 확인한다. 단순히 아직 순서가 오지 않은 일반 작업은 부채로 만들지 않는다.
- 추적자는 중복을 확인해 중요한 문제만 부채 파일로 만들고 경로를 응시자에게 알린다. 작업 담당자는 다음 갱신 시 자신의 보고서에 경로를 연결한다. 추적자는 작업 보고서를 직접 수정하지 않는다.
- 부채가 해결·검증되어 `debt/solved/`로 옮겨지면 추적자는 새 경로를 알리고, 담당자는 다음 갱신 시 연결 경로를 수정한다. 갱신 전 경로가 없으면 같은 이름의 `debt/solved/`도 확인한다. 담당자가 종료했거나 갱신할 수 없으면 추적자는 보고서를 고치지 않고 공통 기록이나 최종 보고에 새 경로를 남긴다.

## 작성 시점과 내용

작업 시작 시 목표·수정 범위·공통 계약을 짧게 적고, 중요한 결정·계약 변경·검증·작업 단위 완료·중단 때 갱신한다. 마지막 갱신 시각 또는 증가하는 버전을 바꾼다. 상태는 전체 작업의 진행 상태이며 검증 성공과 별개다. 코드를 수정하기 전에 완료로 기록하지 않는다.

```markdown
# 작업명

- 담당: 현재 작업 담당자 또는 세션 (필요할 때)
- 갱신: 2026-01-01 12:00 KST 또는 버전 1
- 상태: 진행 중 / 완료 / 차단
- 목표·담당 범위:

## 수행 및 구현
- 완료한 작업:
- 수정·생성한 실제 파일과 함수:
- 입력·출력 또는 공통 계약 변경:

## 결정
- 선택·이유와 실제 검토한 대안:
- 가정·한계:
- AI 제안 검증: 실제로 확인한 제안, 대조 근거·실제 결과, 채택·수정·기각 여부 (해당할 때)

## 검증
- 입력·기대값의 근거·실행한 명령 또는 직접 확인 절차:
- 실제 결과: 성공 / 실패 / 미실행과 이유
- 테스트·결과 위치 및 마지막 관련 변경 후 재검증 여부:

## 남은 문제와 전달
- 남은 일반 작업 또는 확인이 필요한 문제: 한 줄 요약과 부채 등록 요청 또는 부채 파일 경로
- 다른 세션에 필요한 변경:
- 관련 부채 파일: 해당 시 현재 경로 (상세와 최신 상태는 부채 파일 참조)
```

예시는 형식일 뿐이며 시각과 경로는 실제 값으로 바꾼다. 완료한 작업이 아직 없다면 그렇게 표시한다. 실행하지 않은 테스트와 관찰하지 않은 화면은 미실행·미확인으로 적고, 비밀 값·불필요한 개인정보·대량의 로그는 남기지 않는다. AI 제안은 중요한 사례 중 실제로 확인한 것만 기록하고, 근거·결과를 추측하거나 모든 제안의 기록을 요구하지 않는다. 기존 상세 증거가 있으면 내용을 복사하지 말고 경로와 실제 결과를 짧게 연결한다.

## 추적 세션 운영

총괄 또는 지정된 한 세션이 추적자다. 응시자가 작업 착수·중요 변경·작업 완료·통합 전후에 추적을 요청한다. 사용 가능한 자동 알림이나 감시가 확인되지 않았다면 대기 중 자동으로 감시하거나 스스로 재개한다고 가정하지 않는다.

1. 보고서의 최신 갱신 값과 내용을 확인하고, 작업 중인 보고서는 중간 상태일 수 있으므로 잠시 후 다시 확인한다. 각 보고서의 갱신 값과 대조 시점은 추적자가 관리하는 기존 과제 문서에 간단히 남겨 다음 확인에 활용한다. 변하지 않은 보고서는 필요한 경우에만 다시 조사한다. 갱신 값은 신호일 뿐이며 동시 수정이나 갱신 누락이 없는지 중요한 항목은 실제 내용도 확인한다.
2. 작업별 실제 파일·호출 관계와 보고 내용을 대조한다. 보고된 선택 이유는 작성자의 보고로 취급하고, 테스트·측정은 명령과 결과 또는 독립 재실행으로 확인한 범위만 검증 사실로 기록한다.
3. 공통 계획·설명 근거에 중요한 변경과 출처를 연결한다. 불일치·미확인과 다른 세션에 전달할 내용을 응시자에게 알린다. 추적자는 각 작업자가 소유한 코드나 보고서를 임의로 수정하지 않는다.
4. 중요한 결함·임시 처리·미검증은 중복 여부를 확인한 뒤 [부채 지침](../debt/README.md)에 따라 추적자 한 명이 기록하고 번호를 관리한다. 생성·해결 시 현재 경로를 응시자에게 알려 작업 담당자가 다음 갱신에 연결하게 한다. 담당자가 갱신할 수 없다면 공통 기록이나 최종 보고에 경로를 남긴다. 보고서의 모든 미완료 항목을 자동으로 부채로 만들지 않는다. 수정 후 실제 검증이 끝난 경우에만 해결된 부채로 처리한다.
5. 통합·제출 전 최신 보고서와 실제 변경, 마지막 관련 변경 후의 검사 결과를 다시 확인한다. 현재 코드와 맞지 않는 과거 검증은 미검증으로 표시한다.

## 요청 예시

작업 세션:

> `docs/work/README.md`를 읽고 내가 배정한 `docs/work/<작업명>.md`에 작업 시작·주요 결정·검증·완료 또는 중단 시 실제 상태를 갱신해라. 네 보고서만 수정하고 중요한 결함과 미검증을 남겨라. 검증하지 않은 것은 추측하지 마라.

추적 세션:

> `docs/work/README.md`에 따라 작업 보고서의 갱신 사항과 실제 파일·검증 근거를 확인해라. 공통 문서에는 핵심 근거를 연결하고 중요한 미해결 문제만 중복 없이 `docs/debt/`에 기록해라. 불일치·미확인과 내가 다른 세션에 전달할 내용을 알려줘. 다른 세션의 보고서와 작업 중인 코드는 수정하지 마라.
