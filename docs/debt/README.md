# 기술 부채 기록

구현 과정에서 발견한 중요한 기술적 부채를 과제 작업 공간에 짧게 기록하고, 위험도와 남은 시간에 따라 해결·검증한다.

## 기록할 항목

- 임시 구현, 하드코딩, 중복 코드, 구조·의존성의 타협 등 이후 오류나 수정 비용을 초래할 수 있는 부분.
- 미해결 결함, 누락된 예외·경계 처리, 성능·보안·데이터 무결성 문제.
- 확인되지 않은 요구사항·가정, 명세와 구현의 차이, 빠졌거나 실패한 검증.
- AI 생성 결과 중 근거 또는 이해가 부족한 핵심 로직과 통합 과정에서 발견한 불일치.

단순한 취향 차이나 과제에 필요 없는 개선은 추가하지 않는다. 사실·가정·미확인을 구분하고 민감 정보는 기록하지 않는다.

## 파일 작성

- 의미 있는 부채 한 건당 이 폴더에 `01-문제명.md`, `02-문제명.md`처럼 파일을 만든다. 번호는 생성 순서이며 위험도나 처리 순서가 아니다.
- 미해결 파일과 `solved/`의 번호를 모두 확인하고 가장 큰 번호 다음 번호를 사용한다. 삭제된 번호는 재사용하지 않으며, 100개 이상이면 `100`부터 이어간다. 파일을 만든 뒤에는 위험도가 바뀌거나 파일을 이동해도 번호를 유지한다.
- 동시에 작업할 때는 한 담당자가 번호를 배정하거나 파일 생성을 직렬화한다. 같은 번호가 생겼다면 내용을 보존하고 중복 여부를 확인한 뒤 새 번호를 부여한다.
- 기존 부채 관리 위치나 과제·시험 규칙이 있으면 이를 우선한다. 동일한 문제는 기존 파일을 갱신한다. 해결된 문제가 재발하면 원래 파일을 이 폴더로 되돌리고 재발 근거와 다음 조치를 갱신한다.

## 위험도 기준

영향과 발생 조건을 고려해 1~5점으로 평가하고 근거를 짧게 남긴다. 확인되지 않은 영향이나 발생 가능성은 가정으로 표시하며, 새로운 근거가 나오면 점수를 갱신한다.

| 점수 | 기준 | 처리 방향 |
|---|---|---|
| 5 | 보안·데이터 손상 또는 필수 기능에 심각한 영향 | 즉시 해결 우선 |
| 4 | 주요 기능 오류나 결과 정확성에 큰 영향 | 제출 전 해결 우선 |
| 3 | 특정 조건의 기능 오류나 상당한 유지보수 부담 | 남은 시간과 영향에 따라 처리 |
| 2 | 영향 범위가 작고 우회 가능한 문제 | 높은 위험도 처리 이후 검토 |
| 1 | 현재 결과에 미치는 영향이 작은 구조·정리 문제 | 필요할 때 개선 |

## 개별 파일 양식

파일 맨 위에 위험도를 표시하고, 나머지는 필요한 만큼 간결하게 작성한다.

```markdown
# 부채 제목

- 위험도: 1~5/5 — 판단 근거와 미확인 사항

## 문제와 영향
문제, 발생 조건과 사용자·기능에 미치는 영향.

## 위치
관련 파일 또는 기능.

## 다음 조치
해결 방법 또는 확인할 사항.

## 해결 및 검증
수정 내용, 실제 수행한 검증과 결과. 수행하지 않았다면 미수행으로 표시.
```

## 처리 방법

1. 발견 시 문제, 위치, 영향, 위험도와 다음 조치를 기록한다. 중복 항목은 합친다.
2. 위험도가 높은 미해결 항목부터 확인하되, 제출·필수 기능·정확성·보안에 미치는 영향과 남은 시간을 함께 고려한다.
3. 수정 후 관련 기능과 회귀 위험을 검증하고 실제 결과를 기록한다. 수정만 했거나 검증하지 못했으면 수행 내용과 남은 검증을 기록하고 이 폴더에 남긴다. 해결·검증을 완료하면 같은 번호와 파일명을 유지해 `solved/`로 이동한다.
4. 작업 전환과 제출 전에 미해결·미검증 항목과 영향을 인계하고 최종 보고한다. `solved/`의 해결 파일은 이력으로 유지한다.
