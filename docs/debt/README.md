# 기술 부채 기록

빠른 구현 과정에서 발견한 중요한 부채를 과제 작업 공간에 짧게 기록하고, 우선순위에 따라 해결·검증한다. 이 파일은 양식이다. 시험 규칙과 과제의 기존 부채 관리 위치가 우선하며, 허용되는 경우에만 이 양식을 과제의 `docs/debt/README.md`에 복사한다. 기존 파일은 덮어쓰지 않는다.

## 기록할 항목

- 임시 구현, 하드코딩, 중복 코드, 구조·의존성의 타협 등 이후 오류나 수정 비용을 초래할 수 있는 부분.
- 미해결 결함, 누락된 예외·경계 처리, 성능·보안·데이터 무결성 문제.
- 확인되지 않은 요구사항·가정, 명세와 구현의 차이, 빠졌거나 실패한 검증.
- AI 생성 결과 중 근거 또는 이해가 부족한 핵심 로직과 통합 과정에서 발견한 불일치.

단순한 취향 차이나 과제에 필요 없는 개선은 추가하지 않는다. 사실·가정·미확인을 구분하고 민감 정보는 기록하지 않는다.

## 처리 방법

1. 발견 즉시 항목, 위치, 영향, 우선순위와 다음 조치를 기록한다. 중복 항목은 합친다.
2. 제출·필수 기능·정확성·보안에 영향을 주는 문제를 먼저 해결한다. 시간 대비 영향이 작은 개선은 보류할 수 있다.
3. 수정 후 관련 기능과 회귀 위험을 검증하고 실제 결과를 기록한다. 수정만 했거나 검증하지 못했으면 미해결 또는 미검증으로 남긴다.
4. 작업 전환과 제출 전에 목록을 살펴 미해결·미검증 사항과 영향을 인계하고 최종 보고한다.
